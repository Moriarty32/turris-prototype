# Туррис — демонстрационный сайт

Многостраничный прототип по согласованной архитектуре и дизайн-референсу главной страницы.

**Сайт:** https://moriarty32.github.io/turris-prototype/

## Что реализовано

- 109 HTML-страниц на 22 типах страниц, четыре московских отеля и 21 категория номера.
- Предложения, семьи, командировки, группы, длительное проживание, справка и 16 материалов гида.
- Выбор дат, взрослых и возраста детей; сохранение контекста и выбранной категории в пределах вкладки.
- Сравнение объектов, фильтры гида, поиск, галерея, адаптивное меню и двухэтапная демонстрация групповой заявки.
- Статический HTML, мобильная версия, семантические заголовки, noindex для всего прототипа.
- Обновление 29.10.2026: общая система оформления на Manrope, закреплённая шапка с выделенным меню, активными разделами и подробными подменю.
- Анимации кнопок, ссылок, изображений и появления блоков; поддержка `prefers-reduced-motion` и клавиатуры.
- Интерактивная карта четырёх отелей на главной, в каталоге и контактах; выбор маркера связан с карточкой, фильтрами каталога и маршрутами.
- На мобильной главной карта заменяет фотографию первого экрана: четыре видимых названия и отметки выбирают отель в форме, форма обновляет карту. Выбранная карточка содержит адрес, условия, номера, маршрут и переход к датам. При расширении экрана та же карта возвращается в нижний блок без дублирования.
- Компактная компоновка: четыре близкие к квадрату карточки в ряд на широком экране, переключение «Карточки / На карте», соседние блоки предложений и уменьшенные отступы на всех шаблонах.
- Выбранный отель виден во всех формах и синхронизируется при изменениях дат/гостей; есть явный сброс фильтра и переход прямо к таблице сравнения.
- Гид: компактные карточки и поиск по содержанию; все 16 статей получили краткий ответ, таблицу выбора, оглавление, индивидуальный чек-лист и источники. Четыре прогулки дополнены опорными точками и маршрутами. Фото статьи — 230×160 px на компьютере и 84×60 px на телефоне. Решения и источники: `docs/guide-design.json`.
- Аудит изображений: 21 фотография категории подключена из полного официального оригинала; для 28 используемых изображений подготовлены WebP-версии. Исправлены растянутые блоки, добавлен полный фасад и отдельный снимок номера на странице отеля. Размытый фасад Петровского заменён подписанной ИИ-реконструкцией по исходному снимку.

Это прототип с действующим бронированием TravelLine: цены, наличие, оформление и оплата внутри модуля настоящие. Формы обращений вне TravelLine демонстрационные: заявки и данные в CRM не отправляются. Не отправляйте тестовые брони и не проводите тестовые платежи в рабочем модуле.

## Изображения

Сначала определены блоки, размеры и кадрирование в `docs/image-plan.json`. Четыре используемые иллюстрации созданы встроенным Imagegen; размер каждой проверен: **1536×1024 px**. Финальный первый экран использует `assets/hero-room-v2.png`, исходный вариант сохранён отдельно. Промпты и уточнение света включены в план изображений.

25 фотографий фасадов и категорий получены с официальных страниц `turris.online`; источники записаны в `data/asset-sources.json`. Эти фотографии не объявляются изображениями с открытой лицензией. Иллюстрации концепции помечены в интерфейсе и не подтверждают реальные свойства номера.

Обновление качества от 29.10.2026: `data/image-delivery.json` определяет актуальные файлы, источники, размеры и варианты загрузки поверх исходного реестра. `scripts/prepare_images.py` готовит только пропорциональные уменьшения и WebP-кодирование, без кадрирования или дорисовки комнат. Фасад `assets/petrovsky-restored.png` создан встроенным Imagegen по `assets/petrovsky.png`; результат 2172×724 px и точный промпт записаны в `docs/image-quality-plan.json`. Запрошенный мастер 3072×1024 не был получен: фактический размер проверен и превышает требуемые 1296×432 для основного блока при 2x. Исходный снимок сохранён, реконструкция явно подписана во всех местах использования.

## Сборка и проверка

```powershell
python -m pip install -r requirements.txt
python scripts/build.py
python scripts/serve.py 4173
```

Открыть http://127.0.0.1:4173/turris-prototype/ . Сгенерированный сайт находится в `dist/`.

В другом терминале, при наличии Chromium для Playwright:

```powershell
python -m playwright install chromium
python scripts/qa.py
python scripts/qa_experience.py
python scripts/qa_compact.py
python scripts/qa_mobile_hero_map.py
python scripts/qa_guide.py
python scripts/qa_images.py
```

Проверки: все локальные ссылки и изображения, 109 страниц, один H1, noindex, 22 типа страниц в desktop/mobile, отсутствие горизонтального переполнения, даты/гости/категория, форма группы, поиск и фильтры. Результаты локально в `.qa/`.

## Исследование и карта

Исследование пяти гостиничных сайтов и применённые решения: [PDF](docs/Turris-premium-design-research.pdf), [машиночитаемый источник](docs/premium-research.json). Опубликованный отчёт: https://moriarty32.github.io/turris-prototype/research/premium-design-research.html . Пересборка отчёта в Windows: `python scripts/research_report.py` (ReportLab, системный Arial).

Координаты и ссылки на первоисточники: `data/map-locations.json`. Это расположение организации, не подтверждённый доступный вход или парковка. Исходные данные turris.online содержали расхождения координат, поэтому точки сверены отдельно. Карта загружается при появлении в области просмотра; при ошибке остаются адреса и внешние маршруты. На телефоне перемещение карты включается явно, чтобы сохранить прокрутку страницы.

Leaflet 1.9.4 и лицензия находятся в `assets/vendor/leaflet/`; Manrope и OFL — в `assets/fonts/`. Тайлы: OpenStreetMap, с видимой атрибуцией и обычным браузерным кешированием. Нет предзагрузки областей, офлайн-загрузки или геолокации гостя. Автотесты подменяют/блокируют тайлы и не сканируют публичный сервис. Для крупной рекламной нагрузки следует выбрать провайдера с подходящими условиями; `tile_url` вынесен в конфигурацию.

## Страницы отелей по референсу

Четыре обзорные страницы используют `scripts/hotel_detail.py`, индивидуальные сведения из `data/hotel_details.py` и изолированные `assets/hotel-detail.css` / `hotel-detail.js`. Галерея, горизонтальные категории, форма с сохранением выбранного номера, карта одного отеля, услуги, правила и FAQ адаптированы для телефона и компьютера. Карта поддерживает разворот и выход по Escape; галерея — стрелки клавиатуры и возврат фокуса. Без JavaScript фотографии и категории открываются обычными ссылками.

Источники и проверенные поля: `docs/hotel-detail-sources.json`; решения по структуре и размерам изображений: `docs/hotel-detail-design.json`. Использованы настоящие фотографии номеров из существующего набора; ранее восстановленный фасад Петровского сохраняет видимую подпись. Новые вымышленные интерьеры и отзывы не добавлялись.

Проверка: `python -X utf8 scripts/qa_hotel_detail.py` при запущенном локальном сервере. Отчёт охватывает четыре отеля на ширинах 320, 390, 768, 1024 и 1440 px. Общая проверка изображений: `scripts/qa_images.py`.

## Страница бронирования по референсу

`scripts/booking_page.py` и `assets/booking.css` / `booking.js` задают общую страницу бронирования и четыре входа из отелей. Выбор синхронизирован между формой, карточками и картой. Категории обновляются на месте, выбранный номер сохраняется при изменении дат, устаревшие результаты скрываются до повторного поиска. Промокод хранится только в текущей вкладке; его применимость и скидка не имитируются. Данные гостя, оплата и подтверждение остаются на официальном сайте.

Спецификация: `docs/booking-reference-design.json`. Проверка шести размеров экрана, параметров поездки, карты и восстановления после ошибки: `python -X utf8 scripts/qa_booking_reference.py`.

## Публикация

GitHub Pages использует статическую ветку `gh-pages`, собранную из `dist/`. Основная ветка содержит исходники. Перед обновлением пересобрать и проверить изменённые сценарии.

```powershell
git subtree split --prefix dist -b deploy-next
git push origin deploy-next:gh-pages
```

Путь `/turris-prototype` задан в `scripts/build.py`. Перед production-переносом заменить демонстрационные формы, подключить официальную интеграцию бронирования, утвердить факты/условия/юридические документы, проверить изображения, canonical, sitemap и индексацию.

## Предложения по семейному референсу

19 страниц используют `scripts/offers_page.py`, индивидуальные сценарии и условия из `data/offer_details.py`, изолированные `assets/offers.css` / `offers.js`. Семейная страница содержит четыре категории, явный ввод возраста детей, карту двух отелей, условия, FAQ и повторный подбор. Даты, гости и выбранная категория переходят в бронирование; семейный сценарий ограничивает результаты соответствующими категориями. Длительное проживание проверяет срок от 21 ночи, группы используют демонстрационный запрос расчёта. Каталог, акции и программы лояльности адаптированы к своим условиям.

Источники: `docs/offers-reference-sources.json`. Спецификация и размеры изображений: `docs/offers-reference-design.json`. Использованы имеющиеся качественные фотографии номеров; новая генерация не требовалась. Недоступная акция на осенние каникулы отмечена как неподтверждённая.

Проверка: `python -X utf8 scripts/qa_offers_reference.py` при запущенном сервере. Проверяются 19 страниц на четырёх ширинах и сквозные сценарии выбора. Реальная стоимость, оплата и подтверждение остаются на официальном сайте.

## Главная по новому референсу

`scripts/home_page.py`, `assets/home.css` и `assets/home.js` задают главную с плавающей шапкой, тёмной панелью бронирования, двумя колонками карточек и картой с раскрывающимися адресами. Сохранены меню, поиск, помощь, управление бронью, даты и возраст детей, синхронизация двух форм, сравнение отелей, маршруты и все переходы. На главной переключатели карточек/карты ведут к соответствующему разделу; на странице каталога сохраняется переключение представлений. Мобильная версия переносит одну существующую карту на первый экран вместо фотографии.

Спецификация: `docs/home-reference-design.json`. Использованы настоящие фотографии Тверской; существующая реконструкция фасада Петровского сохраняет подпись. Проверки: `qa.py`, `qa_home_reference.py`, `qa_mobile_hero_map.py`, `qa_experience.py`, `qa_compact.py`, `qa_images.py` при запущенном локальном сервере.

## Статьи по новому референсу

Все 16 статей используют `scripts/article_page.py`, `assets/article.css` и `assets/article.js`: компактный первый экран, краткий ответ и содержание, таблица, интерактивная карта, нумерованные рекомендации, чек-лист с прогрессом, подбор номера, источники и три связанных материала. Индивидуальные тексты, таблицы и прогулочные маршруты сохранены. Каталог гида сохраняет поиск и фильтры.

Карта включает подходящие к теме адреса: четыре для выбора района, два для семейных материалов, один для прогулки от конкретного отеля. Выбор синхронизируется с формой; на телефоне адреса переключаются кнопками над картой. Даты и возраст детей переходят в демонстрационное бронирование. Отметки чек-листов сохраняются отдельно по статье в текущей вкладке.

Спецификация: `docs/article-reference-design.json`; результаты: `docs/article-reference-verification.json`. Проверки при запущенном сервере: `python -X utf8 scripts/qa_guide.py`, `scripts/qa_article_reference.py`, `scripts/qa.py`, `scripts/qa_images.py`.

## Контакты сети по референсу

`scripts/contacts_page.py`, `assets/contacts.css` и `assets/contacts.js` задают страницу `/contacts/`: отдел бронирования, карта с прямыми телефонами администраторов, четыре карточки, выбор темы обращения, форма, FAQ и документы. На телефоне отели переключаются над картой; на компьютере раскрывается карточка с фотографией. Выбор связан с полем отеля в форме, адреса и email можно копировать. Телефоны, адреса, парковка Лубянского и отсутствие лифта в Таганском сверены с официальными страницами.

Форма проверяет контакт, сообщение и согласие, показывает явный результат «Сообщение не отправлено» и позволяет вернуться к редактированию. Запросы и персональные данные не отправляются и не записываются в хранилище браузера. Без JavaScript доступны прямые телефоны, почта и маршруты; форма отключена.

Источники, размеры изображений и сценарии: `docs/contacts-reference-design.json`. Проверка: `python -X utf8 scripts/qa_contacts_reference.py`; отчёт — `docs/contacts-reference-verification.json`. Индивидуальные страницы проезда отелей сохраняют свой текущий формат.

## Общая система интерфейса

Все 109 страниц используют одну шапку и подвал из `scripts/navigation.py`. Общие цвета, размеры текста, кнопки, отступы, эффекты и адаптивные правила находятся в `assets/design-system.css`; обработчики меню, клавиатуры и появления блоков — в `assets/design-system.js`. Локальная навигация по разделам отеля и предложения сохраняется внутри страницы. Основное меню доступно и без JavaScript.

Исследование и решения: `docs/global-ux-audit.html` (публикуется в `/research/global-ux-audit.html`). Общая проверка: `python -X utf8 scripts/qa_design_system.py`. Изменения общих примитивов следует проверять совместно с функциональными наборами страниц; результаты этой итерации — `docs/global-design-verification.json`.

## Выдача выбранного отеля

В бронировании категории показываются только после выбора одного отеля. Общей выдачи номеров четырёх объектов нет. Карточки других адресов открываются по кнопке «Сменить отель»; смена через форму, карточку или карту удаляет прежние результаты, сохраняя даты и гостей. Состояние обновляется в URL, а запоздалый ответ загрузки не возвращает чужие категории. Проверки: `scripts/qa_booking_scope.py`, `scripts/qa_booking_reference.py`; результат — `docs/booking-selection-verification.json`.

## Действующее бронирование TravelLine

Публичные контексты действующего сайта подключены для всех четырёх отелей. Общие формы сайта передают отель, даты, взрослых, число и возраст детей в `/bronirovanie/`. Промокод передаётся при поиске; наличие скидки подтверждает TravelLine. Результаты ограничены одним выбранным отелем. Цены не записаны в коде и не кэшируются прототипом.

`assets/booking-widget.html` и `booking-widget.js` изолируют экземпляры поставщика при смене отеля. Высота и этап сообщаются родительской странице с проверкой origin и окна-источника. Данные гостей и платежи обрабатывает TravelLine. Есть загрузка, ошибка, отсутствие предложений, повторная попытка и ссылка на официальный модуль с теми же параметрами.

Внутреннее оформление TravelLine сохранено: для изменения темы нужен кабинет отеля, для собственного интерфейса живых тарифов — согласованный API. Категория с предыдущей страницы показана как ориентир, но не предвыбрана: проверенных идентификаторов TravelLine для её сопоставления нет. Изменения параметров внутри внешнего модуля не синхронизируются обратно с формой прототипа; итоговый состав брони проверяется в TravelLine.

Источники и границы интеграции: `docs/live-booking-integration.json`. Проверки: `scripts/qa_booking_scope.py`, `scripts/qa_booking_reference.py`, `scripts/qa_live_booking.py`. Последняя проверяет реальные цены и переход к тарифам, не оформляя бронь и не проводя платёж.
